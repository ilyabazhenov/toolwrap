How it works

One file per project. One MCP server for the agent.

A set is a TOML file in ~/.mcphub/sets. toolwrap launches the servers it lists, injects the set’s keys, applies your edits and exposes the result to the agent as a single MCP server. Everything in the window is also in the CLI.

One server per set

Clients see a set as one MCP server: over stdio through mcphub-bridge, or HTTP on 127.0.0.1.

Processes by credentials

Ten sets on one Jira account share one process; different keys get different processes; share = root gives each worktree its own.

Edits live in the gateway

Rewrite descriptions, pin arguments, hide tools, prompts and resources — without forking a server.

Project context first

Text, files, a command or a tool call — the agent gets it at the start of the session, unasked.

Security model

The agent does the work. The rules stay yours.

  • Local only

    The daemon listens on a local socket or named pipe; HTTP binds to 127.0.0.1. No cloud, no account.

  • Secrets in the OS keychain

    Keychain, Credential Manager or Secret Service. Config files only hold references like secret:alpha/JIRA_TOKEN.

  • Approval in any client mode

    toolwrap asks even when the agent runs in auto, bypass or yolo mode, or the client allows every tool.

  • Answers only from the window

    An approval counts only in toolwrap’s own card — not in the terminal the agent controls.

  • Weakening is held

    Lifting an approval, enabling a disabled tool, turning the gate off or adding a server waits for a human “Apply”.

  • A log with redacted secrets

    Every call with its arguments and outcome — filter by set, server, failures and approvals.

FAQ

Frequently asked questions

What is an MCP gateway?

An MCP gateway sits between AI clients and MCP servers. Instead of configuring every server in every client, you connect the client to the gateway once, and the gateway decides which servers, credentials and rules apply to each project.

Which clients does toolwrap work with?

Any MCP client: Claude Code, Codex, Cursor, VS Code, Gemini CLI. Stdio clients connect through mcphub-bridge, others over HTTP on 127.0.0.1. Existing servers can be imported from Claude Code and Codex.

Where are tokens and API keys stored?

In the OS secret store: Keychain on macOS, Credential Manager on Windows, Secret Service on Linux. On import, toolwrap removes tokens from client configs; the call log redacts secrets.

Can the agent turn approvals off by itself?

No. An edit that weakens protection — in the set file, through the CLI or by adding a server — is not applied until a human clicks Apply in the toolwrap window. Until then the previous policy holds.

What happens if I am away from the computer?

The approval card waits 240 seconds, then the call is denied and the model gets a clear reason. Nothing risky runs without a human.

Do I need to change my MCP servers?

No. toolwrap runs ready-made servers — an npx or uvx command, a binary or a remote URL — and has no integrations of its own. Description edits and pinned arguments are applied by the gateway, not the server.

Is there a cloud or sync?

No. The daemon runs on your machine and listens on a local socket. To move sets to another machine or share them with a team, export them to a file.
