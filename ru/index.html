Как устроено

Один файл на проект. Один MCP-сервер для агента.

Набор — это TOML-файл в ~/.mcphub/sets. toolwrap запускает перечисленные в нём серверы, подставляет ключи набора, применяет ваши правки и отдаёт агенту всё это как один MCP-сервер. Всё, что есть в окне, есть и в CLI.

Один сервер на набор

Клиент видит набор как один MCP-сервер: по stdio через mcphub-bridge или по HTTP на 127.0.0.1.

Процессы по ключам

Десять наборов на одном аккаунте Jira делят один процесс; разные ключи — разные процессы; share = root даёт каждому worktree свой.

Правки живут в шлюзе

Перепишите описания, закрепите аргументы, спрячьте инструменты, промпты и ресурсы — без форка сервера.

Сначала контекст проекта

Текст, файлы, команда или вызов инструмента — агент получает их в начале сессии, без просьбы.

Модель безопасности

Работу делает агент. Правила остаются вашими.

  • Только локально

    Демон слушает локальный сокет или named pipe, HTTP — только на 127.0.0.1. Без облака и аккаунта.

  • Секреты в системном хранилище

    Keychain, Credential Manager или Secret Service. В файлах — только ссылки вида secret:alpha/JIRA_TOKEN.

  • Подтверждение в любом режиме клиента

    toolwrap спрашивает, даже когда агент запущен в auto, bypass или yolo, или клиент разрешил все инструменты.

  • Ответ — только из окна

    Подтверждение засчитывается только в карточке toolwrap, а не в терминале, которым управляет агент.

  • Ослабление задерживается

    Снять подтверждение, включить выключенный инструмент, отключить gate или добавить сервер можно только после «Применить» человека.

  • Журнал без секретов

    Каждый вызов с аргументами и исходом — с фильтрами по набору, серверу, сбоям и подтверждениям.

Как начать

Три шага. Агент ничего не заметит

  1. Установите приложение

    toolwrap живёт в строке меню и обновляется сам — когда вы нажмёте «Обновить».

  2. «Перенести из клиентов»

    Серверы из Claude Code и Codex переезжают в наборы, ключи — в Keychain, из конфигов они исчезают.

  3. Работайте как раньше

    Агент открывает ту же папку и получает свой набор. А вы решаете только то, что важно.

Вопросы

Частые вопросы

Что такое MCP-шлюз?

MCP-шлюз стоит между AI-клиентами и MCP-серверами. Вместо того чтобы настраивать каждый сервер в каждом клиенте, вы один раз подключаете клиент к шлюзу, а шлюз решает, какие серверы, ключи и правила действуют в каждом проекте.

С какими клиентами работает toolwrap?

С любым MCP-клиентом: Claude Code, Codex, Cursor, VS Code, Gemini CLI. Клиенты со stdio подключаются через mcphub-bridge, остальные — по HTTP на 127.0.0.1. Перенести уже настроенные серверы можно из Claude Code и Codex.

Где хранятся ключи и токены?

В системном хранилище: Keychain на macOS, Credential Manager на Windows, Secret Service на Linux. При переносе toolwrap удаляет токены из конфигов клиентов, в журнале секреты замазаны.

Может ли агент сам отключить подтверждение?

Нет. Правка, которая ослабляет защиту — в файле набора, через CLI или новым сервером, — не применяется, пока человек не нажмёт «Применить» в окне toolwrap. До этого действует прежняя политика.

Что будет, если я отошёл от компьютера?

Карточка ждёт ответа 240 секунд, затем вызов отклоняется, и модель получает понятную причину. Опасное без человека не выполняется.

Нужно ли менять сами MCP-серверы?

Нет. toolwrap запускает готовые серверы — команду npx или uvx, бинарь или удалённый URL — и не пишет своих интеграций. Правки описаний и закреплённые аргументы применяет шлюз, а не сервер.

Есть ли облако или синхронизация?

Нет. Демон работает на вашей машине и слушает локальный сокет. Перенести наборы на другую машину или в команду можно экспортом в файл.
